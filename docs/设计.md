# Sideline 开发说明

本文描述 1.0.0 的维护结构与发布约束。行为基准为 0.10.10；本轮只删除有调用证据支持的冗余、整理文档和独立构建，不改变有效配置、会话格式或用户交互。清理依据见[清理审计](清理审计.md)。

## 目录与环境

| 目录 | 职责 |
|---|---|
| `src/` | 唯一运行源码；其根目录就是 XPI 根目录 |
| `scripts/` | 静态检查、假宿主测试、构建与发布导出 |
| `test/` | Node 假 Zotero 环境及回归夹具；不依赖外部知识库 |
| `docs/` | 开发、验收、接口和清理依据 |
| `runtime/` | 临时报告、历史基准、XPI 和发布产物；不进入公开源码树 |

支持 Windows、Zotero 10；自动化需 PowerShell、Node.js、Python 3。运行命令见[README](../README.md)。PowerShell 脚本使用 ASCII；源码和文档使用 UTF-8。`src/manifest.json` 与 `src/bootstrap.js` 的版本必须一致。更新运行代码后需重新构建并安装 XPI，不能只修改本地源文件。

## 主调用链

`bootstrap.js` 按显式清单载入 `modules/` 并注册设置、阅读器和 HTTP 端点；禁用时注销。Zotero 沙箱与 Node 假宿主分别提供环境，测试不得把 Node 能力当作 Gecko 已验证能力。

- **界面与材料**：`readerside` 管侧栏，`reader` 管划词弹窗；`functions` 注册四个功能。`inputs` 将文件或标识解析成可见材料，`readertext` 提取页正文及覆盖情况，`context` 组合条目、材料与上下文。失败必须有可读原因，不能把文件路径冒充正文。
- **通道**：`providers` 根据默认通道分流。API 的文字和视觉配置独立，`client` 发起兼容 HTTP 请求。Agent 经安装校验与固定适配器启动，`agentconversation` 管理本篇原生会话，Codex 使用 JSONL，OpenCode/DeepSeek Harness 使用 ACP。DeepSeek Harness 的固定流式模块只传正文，不传思考、工具参数或凭据。
- **保存**：`session` 管内存消息，`store` 串行写入文献条目下的 JSON 附件；`excerpt` 创建子笔记，`annotations` 创建批注，`writes` 留写入记录。`summary` 保留结构化总结接口，不能因侧栏删了入口而删除。

DOM 使用 XHTML 命名空间。侧栏只追加插件节点，不改写 Zotero 容器的类名、隐藏属性或样式；用自有类控制显隐，保留重挂载机制。阅读器内部 API 和文件选择器契约会随宿主升级变化，升级后需真机复验。

## 稳定行为与兼容

**设置与状态**：保留有效的旧键读取回退；新键显式清空时不能复活旧值。API 模型可编辑，Agent 模型只能从已读目录选择。Agent 的目录、模型、协议、强度、真实连接测试按顺序反馈；环境或模型变化清除失效状态，过期异步响应不能覆盖新选择。绿色连接状态只能来自真实请求成功。

**会话**：宿主键归一到父文献；每篇最多一场，旧 `sessions` 数组格式保留。加载旧多会话记录时只留最近一场，损坏 JSON 先留 `.corrupt` 再重建。Agent 原生 ID、安装信息及摘要保存在本机映射，正文和图片在 Zotero 附件。重启或停止后继续明确 ID；仅在尚未提交问题的恢复失败阶段重建并提示，不为普通模型错误重发收费请求。清空只重置本篇记忆，不删除用户笔记或既有批注；失败重置不得继续旧讨论。

**定位与写入**：普通引用的完整原文锚点采用严格匹配，失败只跳页。自动高亮沿用当前近似匹配并明确标记；坐标由 PDF 文本片段计算，不能使用模型坐标。划词批注受 `readerAnnotationWrite` 控制，侧栏逐项预览后确认写入不受该开关控制。回答点选写入每次新建子笔记，清空会话不回滚已写笔记。后台结构化总结保留 `structured-summary-v1` 标记、只追加标签和父条目 `Extra` 的 `总结:` 行；默认不覆盖用户已有结果。

**提示词基准**：四功能采用单独偏好覆盖，内置总结模板与 `test/fixtures/summary-prompt.md` 逐字核对。夹具缺失必须使测试失败。更新提示词需同步夹具并说明语义变化；不能重新依赖维护者知识库中的 Skill 文件。

**权限与端点**：安装扫描由用户触发，只允许目录和已校验白名单入口。Agent 默认拒绝文件、终端及未知工具；搜索开关默认关闭，仅打开经过校验的网络工具。插件清理记忆必须核实文献专属目录或会话元信息。HTTP 接口列表见[接口说明](接口.md)，不引入任意命令执行或凭空批注坐标接口。

## 验证与发布

1. 运行静态检查、假宿主测试和构建。只读审计先核实加载清单、动态入口及端点，再由统筹任务执行删除；保留仍有效的外部接口。
2. 通过 `scripts/release.ps1` 从明确允许的项目文件导出独立发布树；排除历史 `runtime`、本机索引、日志、凭据、文献和会话数据。源码包保留有效测试、夹具、许可证及维护说明。
3. 在独立树重新运行检查、测试和构建，连续构建比对 SHA-256，并核对 XPI 中的文件与该树 `src/` 一致。重新运行时不得借用原知识库或历史产物。
4. 按[验收清单](验收.md)安装本次 XPI，记录实际 Zotero、Agent 和模型版本。模型桥接成功不等于设置页、Gecko 子进程、阅读器及写入通过。
5. 向 shiysent-ctrl/Zotero-SideLine 仓库提交独立项目源码；runtime 中的安装包作为 Release 附件，不提交运行目录。保留插件 ID，首发手动安装；Zotero 必需的 HTTPS 更新地址对应仓库 main 分支的 updates.json，源码附空更新列表，不提供自动升级候选。发布附件提供版本化 XPI 与 SHA-256，GitHub 自动提供该标签的源码包。

未完成的真机项目必须在 Release 说明中标明，不能用旧版测试结果填充本版验收。历史基准、日志、探测和索引产物已由维护者确认清理，不随公开源码分发。
