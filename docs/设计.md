# Sideline 开发说明

本文描述当前 1.0.0 覆盖更新版的结构与维护约定。使用与构建见 [README](../README.md)，HTTP 契约见[接口说明](接口.md)，真实宿主验证见[验收清单](验收.md)。

## 入口与职责

`src/bootstrap.js` 按显式模块表装载 `Sideline` 命名空间，注册设置、阅读器事件与本机端点；禁用或退出时中止请求、保存会话并注销界面。`src/` 是唯一运行源码，根目录即 XPI 根目录。

| 模块 | 输入、输出与边界 |
| --- | --- |
| readerside | 阅读器身份、宿主挂载、自愈、材料与界面事件；通过回调连接各模块 |
| reader | 划词弹窗及独立编辑文档，快捷功能仅翻译 |
| readermessages / readermenu | 气泡、排版缓存、引用定位、正文选择/复制、统计；菜单定位及监听清理 |
| readerrequests / readerhighlights | 请求占用、材料准备、流式定稿、失败与停止；高亮分段、批次与重试 |
| readerreplies | 修改提问、保存该回复及对应问题、隐藏普通回答、撤销高亮批次 |
| functions / inputs / context | 四功能定义、材料解析和请求上下文；失败材料不得用路径冒充正文 |
| providers / client | 按通道分流；API 文字与视觉独立，client 处理 HTTP、SSE 和模型预算 |
| agents / agentconversation | 校验安装、选择固定适配器、维护每篇文献的原生会话；Codex 使用 JSONL，OpenCode/DSH 使用 ACP |
| modelrequest / chatservice | 共用预算、用量、历史过滤、请求标识和流式节流；本机问答业务与端点声明分开 |
| session / store / storecodec | 内存消息、附件与串行保存；纯数据清洗、标识与兼容不依赖 Zotero |
| history | 侧栏可见内容检索；原始历史检索及 Markdown/JSON 导出保留独立契约 |
| readertext / prosematch | PDF 原生取文、几何、严格定位；纯数据模块计算同页正文相似范围 |
| highlights / annotations / writes | 解析和准备批注、原生保存、持久写入日志及受保护的批次撤销 |
| excerpt / summary | 新建子笔记；结构化总结的预览与确认提交，保留固定标记和已有结果 |

侧栏主链为 `readerside.send → readerrequests.send → providers`；高亮专用链为 `readerhighlights.sendHighlights → highlights.documentChunks/parse/prepare → highlights.commit → writes.journalAnnotation → annotations.saveJSON`。请求模块接收 `view` 与材料回调，不持有宿主挂载权限。

## 界面与交互

只维护阅读器侧栏和划词弹窗两个界面。节点使用 XHTML 命名空间、自有类和主题变量，不改 Zotero 自有类、hidden 或样式。宿主替换容器后自愈重挂载，卸载移除观察器、计时器、菜单及文档监听。

正文排版共用 `util.markdownToHtml` 和本地 KaTeX，不改写存档 Markdown。流式增量与最终定稿沿用同一渲染路径；未闭合公式暂按文字显示，代码围栏不作为公式解析。划词输入放在本地 `about:blank` iframe 的原生 textarea，隔离阅读器捕获阶段的编辑按键，保留 Enter、Shift+Enter、输入法及 Escape。

气泡正文阻止 pointerdown 冒泡，不取消默认行为，避免宿主 FocusManager 阻断原生拖选。右键菜单仅有“全选、复制”；范围限定当前正文，复制在打开菜单时捕获文字，避免焦点变化丢失选区。沿用共享菜单的点外、Escape 和滚动关闭。

侧栏检索使用 `visibleOnly:true`，用户提问取 display，高亮取可读回执，跳过 uiHidden 消息。结果保留原消息序号并用稳定消息 ID 定位实际气泡；先关闭摘要再测量位置，只滚动插件消息容器。会话更新作废旧查询，迟到响应不恢复摘要。HTTP 检索与导出继续读取原始历史。

## 请求、配置和会话

材料准备开始即占用本篇请求，重复发送不启动第二次取文；准备阶段停止仅标记本任务，有 requestKey 时才取消相应调用。成功、失败和停止均释放占用，错误不能清除其他文献的状态。

有效旧配置继续读取；新字段显式清空不复活旧值。API 模型可编辑，Agent 模型从已读目录选择。目录、模型、协议、思考强度与真实连接按阶段反馈，过期响应不能覆盖新选择；打开设置不启动扫描、推理或会话清空。

每篇文献仅一场会话，宿主键归一到父文献；保留旧 sessions 数组结构，旧多会话只留最近一场。损坏 JSON 先保留 corrupt 副本。正文和图片保存在 Zotero JSON 附件，Agent 原生 ID 和安装映射留在本机。

停止、退出或重启保留原生 ID。仅在问题尚未提交的恢复失败阶段重建一次并补入上下文、红字提示；普通网络或模型错误不自动重发收费请求。清空只重置本篇消息和映射，不删除用户笔记或已有批注。

附件版本沿用 v3。旧消息缺 ID 时加载补齐；uiHidden、localOnly 默认 false，highlightBatch 默认 null。localOnly 回执不进入模型历史，uiHidden 只控制显示。初始 1.0.0 的清洗白名单会丢弃新增显示与批次字段，降级需备份实际会话附件，不能把源码回退视为数据恢复。

store 负责容量限制与串行保存，storecodec 仅处理普通 JSON 数据。普通回答按 flushItem 核验本篇保存结果，保存失败保留内存回答并显示原因。超限裁剪按原时间顺序移除消息前缀，保留最后一条消息、会话和写入日志，不复活已裁剪数据。

## PDF 定位、高亮与撤销

普通完整引文导航采用严格匹配，失败只跳页并提示。自动高亮先精确匹配完整引用，只有零命中才允许同页长正文回退；多重命中、出现序号或边界错误不能由回退绕过。

正文回退按 NFKC、小写及引用编号清理后的有序编辑距离评分，要求至少 30 个长度单位、连续一至三句、最多 1200 个规范化字符，相似度至少 80%，且不同物理位置候选相差至少 10 个百分点。短句、纯公式、跨页或非连续拼接不接受。运算符和标点不参与评分，因此分数不能证明公式语义等价。

摘录和坐标来自实际命中的原生 PDF 字符，裁剪首尾并隔离跨栏矩形；不使用模型坐标、短前缀或字块均分。行末排版连字符可逐处保留或跳过，行内连字符和数学减号保持。零宽组合标记仅在范围内核验同位置、同旋转的基础字符后共用其矩形。sortIndex 带物理页序、字符偏移与页面位置。

高亮需父文献及会话保存。`store.prepareWrite` 在模型请求前实际预检附件写入；失败保留输入，不请求模型。创建批注前持久化 pending 日志，成功后登记 created 状态及真实宿主快照；中断记录不能据预期快照猜测删除。

一次操作的所有正文段归属同一批次，后续分段消息隐藏，UI 仅显示本地回执；原始响应保留为模型历史。失败不自动修复，重试只请求失败或停止段，不重读成功段。

普通回复撤销仅持久化 uiHidden。高亮撤销按该回复绑定批次逐项核验库、附件、批注键和创建快照，保护用户改过的正文、评论、颜色、位置、作者、标签、关系及修改时间；删除、已不存在、已编辑和失败分别统计。清空对话不回滚批注，裁剪消息不保留对应气泡入口。

## 本地计算与维护边界

每个高亮请求持有独立页面缓存，最多保留最近八页，同页并发共用 Promise，失败移除；定位和模型材料共用原生字符，结束或停止清空，重试重新建缓存。匹配阈值、材料预算、分段和模型调用不因缓存改变。

每个阅读器缓存最多 60 条、合计不超过 200 万 HTML 字符的已完成普通回答；正文、页码映射或渲染器变化后失效。只复用字符串，节点和事件重新绑定，隐藏/裁剪和卸载释放缓存。正文评分与存档裁剪有独立参照回归，不能用缓存优化改变数据语义。

19 个本机端点、单参数 init、方法声明和 JSON 响应保持，见[接口说明](接口.md)。无界面入口不代表外部接口无用。总结模板与项目内 fixture 逐字核对，夹具缺失必须失败。

## 检查与交付

`scripts/check.ps1` 检查语法与配置，`scripts/test.ps1` 执行假宿主和安装清单回归，`scripts/build.ps1` 按固定时间戳打包。`scripts/release.ps1` 从允许清单导出独立树，再检查、测试、双重构建并核对所有包内字节，确保不依赖原工作区或历史产物。

提交仅包含源码、资源、有效测试、构建脚本、CI、许可证及当前文档。runtime、索引、日志、缓存、凭据、文献和会话不进入 Git。Git 保留原始换行，XPI 根目录为 src；KaTeX 的许可证与字体必须保留。

Windows CI 只验证并上传候选，不自动发布。真实 Zotero、PDF 写入和模型验收按清单单独记录；未验证项目不能用旧版结果填充。XPI 和校验值作为发布附件，源码通过 Git 交付；当前 updates.json 仍为空更新列表。
